Layer 1 Deep Dive

Identity layer = durable ingredients, not live execution

The identity layer should own the stable things that define who an agent is and what it is allowed to become between runs. It should not own live prompts, active tool instances, or in-flight plans. Those belong to orchestration and execution.

Identity layer at a glance

Purpose

Persist the agent’s authored intent, trust envelope, memory anchors, and topology role.

Output

A compiled identity snapshot that orchestration can load at the start of a turn.

Boundary

No live run state, no worker plans, no concrete prompt bundle, no active tool clients.

Current repo anchors

  • `AgentRecord` and `AgentConfig` already hold instructions, skills, toolConfig, notifications, and schedule.
  • `ConversationThread` + checkpoints already give the lead agent a durable conversational spine.
  • `WorkspaceStore` and `LessonRepository` already separate human-curated knowledge from distilled lessons.
Component A

Agent core profile

  • Agent id, project id, name, description, status
  • Stable purpose statement: what this agent is for
  • Human-facing role label, not runtime mode
Component B

Instruction profile

  • Base instructions and operating principles
  • Style/voice commitments and non-negotiable constraints
  • Mode selection policy may reference this, but mode overlays are not stored here
Component C

Capability envelope

  • Skill references
  • Provider requirements and tool policy catalog
  • Approval posture, delegation rights, and future coordination rights
Component D

Memory anchors

  • Human-curated workspace knowledge
  • Durable lessons and memory summaries
  • Pointers to episodic memory, not the full working set itself
Component E

Conversation anchors

  • Primary thread id and channel metadata
  • Checkpoint summaries, compaction health, token history
  • A durable record of how the user talks to this agent
Component F

Topology profile

  • Peer-agent relationships
  • Pinned specialists metadata
  • Whether this agent may coordinate specific siblings

Identity layer owns

  • Stable authored instructions
  • Policy envelope and connected capability metadata
  • Durable memory and conversation references
  • Team/topology role within the project

Identity layer does not own

  • The actual runtime prompt bundle
  • Concrete tool clients or live credentials in memory
  • Current task plans, worker specs, or run state
  • Pending execution outputs except as linked artifacts

Prompt construction belongs to orchestration. Tool instantiation belongs to execution. Identity owns the durable source material those layers compile and enforce.
