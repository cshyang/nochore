Nochore Layer Model

Identity on top, durable work underneath

One lead agent stays accountable at the surface. Peer agents are visible teammates. Internal workers stay hidden. The runtime is durable and async at the substrate, but the lead agent can still complete bounded work in one turn.

Layer 1

Identity Layer

Owns who the agent is between runs
User-facing

Durable records

  • Agent record, instructions, workspace, memory, learned lessons
  • Primary chat thread and project-level thread references
  • Peer agent roster and role metadata

Contract

  • Never executes tools directly
  • Accepts requests, owns voice, owns accountability
  • Hands intent to orchestration and receives synthesized results back
Layer 2

Orchestration Layer

Decides direct vs coordinate-now vs coordinate-later
Lead-agent runtime

Core records

  • Coordinator run
  • Plan artifact and delegation specs
  • Parent/child linkage and synthesis checkpoints

Contract

  • Must understand before delegating
  • Can wait for bounded child work or detach for long work
  • Owns final synthesis, approval asks, and final answer
Layer 3

Execution Layer

Ephemeral workers and durable peer-agent runs
Mostly internal

Unit types

  • Worker runs: scoped role, narrow tools, structured result
  • Peer-agent runs: sibling agent triggered with its own identity and policy
  • No user-facing worker objects in the product model

Contract

  • Do bounded work only
  • Return artifacts, not final user answers
  • Never exceed granted policy or tool scope
Layer 4

Delivery Layer

Turns work results into product surfaces
Artifacts first, chat second

Outputs

  • Run summaries, findings, publishable artifacts, approval requests
  • Activity feed entries and Needs Input inbox items
  • Chat messages that mirror or summarize durable results

Contract

  • Chat is a surface, not the source of truth
  • Every important outcome exists as a durable record
  • Users can reopen context from a feed item or inbox item
1. Request

User talks to lead agent in chat or a schedule triggers work.

2. Choose mode

Coordinator decides direct, coordinate-now, or coordinate-later.

3. Dispatch

Worker runs or peer-agent runs execute with scoped policy and tools.

4. Synthesize

Lead agent re-enters, judges results, and prepares the real answer.

5. Deliver

Artifacts, approvals, activity, and chat all reflect the same durable outcome.

Policy Flow

Policy flows down from the lead or sibling agent. Workers can only narrow, never widen.

Approval Boundary

Approvals attach to work items and durable records, not to ephemeral prompt state.

Promotion Boundary

Repeated worker patterns may become pinned specialists, then later peer agents, only by confirmation.

The key architectural choice: async substrate, hybrid execution. Build everything on durable child work units, then let the orchestrator wait inline only when the work is small and bounded.
