# Nochore Design Context

## Design Context

### Users

**Two distinct audiences sharing one product:**

1. **Non-technical agent deployers** (primary) — Marketing managers, ops leads, small business owners. They manage clients and want AI agents to handle repetitive analytical work (ad spend monitoring, lead qualification, content scheduling). Their context: busy, task-switching between multiple clients/projects, checking in on agents between meetings. Job to be done: "Tell me if something needs my attention, handle the rest."

2. **Technical extension builders** (secondary) — Developers who build Skills and Policies as typed, composable modules. Their context: SDK documentation, code editors, marketplace publishing. Job to be done: "Let me encode domain expertise as a reusable, sellable agent capability."

The interface must serve the deployer first — they are the daily user. The builder touches the platform less frequently and primarily through code/SDK.

### Brand Personality

**Three words: Calm, Competent, Precise.**

- **Voice**: Confident but never boastful. Direct statements, not hedging. "Your agent found 12 wasteful keywords" not "We think we may have identified some potentially wasteful keywords."
- **Tone**: Like a senior analyst who's already on top of it. The product should feel like it knows what it's doing — the user relaxes because the system exudes competence.
- **Emotional goals**: Trust, relief, quiet confidence. The user should feel "this is handled" when looking at their dashboard. Moments of delight come from craft and polish, not decoration.

### Aesthetic Direction

**Visual tone**: Premium, polished, alive — but never loud. Think Raycast/Arc energy: subtle gradients, personality in details, micro-interactions that reward attention. Every element feels intentional.

**Theme**: Dark mode primary. The existing palette from `prototype.jsx` is the foundation:
- Background: `#0F1117` (deep navy-black)
- Surface: `#1A1D27` / `#222533` (layered depth)
- Accent: `#6C5CE7` (purple — distinctive, not generic blue)
- Semantic: Green `#00D68F` (success/running), Yellow `#FFB800` (attention), Red `#FF6B6B` (error), Blue `#4DABF7` (info)
- Text: `#E8E9ED` (primary), `#8B8D98` (secondary), `#838591` (dim — WCAG AA compliant on both bg and surface)

**Accessibility**: WCAG AA minimum — 4.5:1 contrast for text, 3:1 for UI components and large text. All interactive elements must be keyboard accessible. Respect `prefers-reduced-motion`.

**References**: Raycast / Arc — playful but polished, subtle gradients, personality baked into details, feels alive and premium. The craft is in the micro-interactions, transitions, and how information is layered.

**Anti-references** (what Nochore must NEVER look like):
- **Zapier / Make.com** — No workflow builders with nodes and wires. Agents are briefed conversationally, not programmed visually.
- **Generic SaaS** — No blue gradients, stock illustrations, or cookie-cutter layouts. Nochore should be immediately recognizable.
- **Enterprise dashboards** — No dense data tables, tiny fonts, or gray-everything. Data is interpreted by agents, not dumped on users.
- **Over-designed AI tools** — No glowing orbs, particle effects, or "futuristic" UI. Competence over spectacle. The AI is in the reasoning, not the decoration.

### Design Principles

1. **Agent-first, not data-first.** Users interact with agents, not raw data. Every screen should answer "what does my agent think?" before "what do the numbers say?" Agents interpret; users decide.

2. **Progressive trust.** Start conservative (agent suggests, human approves). Earn autonomy through demonstrated competence. The UI should make this trust gradient visible and controllable.

3. **Conversational over configurational.** Setting up an agent should feel like briefing a colleague, not filling out a form. Natural language first, structured input only when precision is needed.

4. **Quiet until important.** Don't demand attention. Three-tier information hierarchy: Needs Input (yellow) → Auto-Handled (green) → FYI (gray). Most of the time, the system should say "nothing unusual, your agent is watching."

5. **Craft in the details.** The "alive" quality comes from polish: smooth transitions, considered spacing, subtle hover states, thoughtful loading states. Never decoration for its own sake — every animation should communicate state or provide feedback.

### Typography & Spacing

- **Grid**: 8px base unit. Spacing scale: 4, 8, 12, 16, 24, 32, 48, 64
- **Border radius**: 8px (buttons, inputs), 12px (cards, panels), 16px (modals, large containers), 99px (badges, pills)
- **Font**: System font stack (to be refined — consider Inter or similar geometric sans for the final product)
- **Weights**: 400 (body), 600 (headings, labels, emphasis), 700 (hero text)
- **Minimum font size**: 12px (no 11px text — snapped to grid for accessibility and consistency)

### Motion

- **Standard timing**: `0.15s ease` for all transitions (hover, expand, color change)
- All properties use the same timing — no mixed durations within a single interaction
- Respect `prefers-reduced-motion`

### Component Patterns

- **Cards with layered surfaces** — depth via background color steps, not shadows
- **Status dots** — green (running), yellow (attention), red (error), gray (inactive)
- **Insight cards** — three tiers with color-coded headers and always-visible reasoning
- **Badges** — pill-shaped, dim background with saturated text for semantic colors
- **Buttons** — primary (accent fill), secondary (surface + border), ghost (text only)
