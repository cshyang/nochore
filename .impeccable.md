# Nochore Design Context

## Design Context

### Users

**Two distinct audiences sharing one product:**

1. **Non-technical agent deployers** (primary) — Marketing managers, ops leads, small business owners. They manage clients and want AI agents to handle repetitive analytical work (ad spend monitoring, lead qualification, content scheduling). Their context: busy, task-switching between multiple clients/projects, checking in on agents between meetings. Job to be done: "Tell me if something needs my attention, handle the rest."

2. **Technical extension builders** (secondary) — Developers who build Skills and Policies as typed, composable modules. Their context: SDK documentation, code editors, marketplace publishing. Job to be done: "Let me encode domain expertise as a reusable, sellable agent capability."

The interface must serve the deployer first — they are the daily user. The builder touches the platform less frequently and primarily through code/SDK.

### Brand Personality

**Three words: Calm, Competent, Precise.**

- **Voice**: Confident but never boastful. Direct statements, not hedging. "Your agent found 12 wasteful keywords" not "We think we may have identified some potentially wasteful keywords."
- **Tone**: Like a senior analyst who's already on top of it. The product should feel like it knows what it's doing — the user relaxes because the system exudes competence.
- **Emotional goals**: Trust, relief, quiet confidence. The user should feel "this is handled" when looking at their dashboard. Moments of delight come from craft and polish, not decoration.

### Aesthetic Direction

**Visual tone**: Premium, polished, alive — but never loud. Think Raycast/Arc energy: subtle grain texture, personality in details, micro-interactions that reward attention. Every element feels intentional.

**Theme**: Dark mode primary. Warm neutrals with plum undertone.
- Background: `#0E0D12` (deep warm-black, plum undertone)
- Raised: `#15141A` (subtle lift)
- Surface: `#1B1A21` / `#222128` (layered depth via color, not shadows)
- Border: `#2B2935` / `#3A3845` (subtle, warm)
- Accent: `#5A7ACD` (periwinkle blue — distinctive, clear, not generic)
- Accent bright: `#7090E0` (hover/emphasis)
- Semantic: Green `#6CB48A` (success/running), Orange `#E0905A` (attention/needs input), Red `#D97272` (error), Read `#7CA8C4` (passive tools), Write `#C49B7C` (active tools)
- Text: `#ECEAF2` (primary), `#9B97AB` (secondary), `#6B6780` (dim)

**Typography**: Satoshi (headings, bold/semibold) + General Sans (body, regular/medium). Base size 14px (0.875rem). Dramatic scale jumps: display at 2.75rem, hero at 3.5rem. Crisp letter-spacing on display text (-0.03em), wide tracking on overlines (0.06em). Dark mode line-height bumped +0.05.

**Accessibility**: WCAG AA minimum — 4.5:1 contrast for text, 3:1 for UI components and large text. All interactive elements must be keyboard accessible. Respect `prefers-reduced-motion`.

**Anti-references** (what Nochore must NEVER look like):
- **Zapier / Make.com** — No workflow builders with nodes and wires
- **Generic SaaS** — No blue gradients, stock illustrations, or cookie-cutter layouts
- **Enterprise dashboards** — No dense data tables, tiny fonts, or gray-everything
- **Over-designed AI tools** — No glowing orbs, particle effects, or "futuristic" UI
- **AI slop** — No purple-to-blue gradients, glassmorphism, neon accents on dark, gradient text on metrics

### Design Principles

1. **Agent-first, not data-first.** Users interact with agents, not raw data.
2. **Progressive trust.** Start conservative, earn autonomy visibly.
3. **Conversational over configurational.** Briefing > forms.
4. **Quiet until important.** Three tiers: Needs Input (orange) → Auto-Handled (green) → FYI (dim text).
5. **Craft in the details.** Smooth transitions (0.15s ease), 8px grid, subtle hover states, grain texture overlay, gentle entrance animations (6px, 0.4s).

### Typography & Spacing

- **Fonts**: Satoshi (headings) + General Sans (body) via Fontshare
- **Grid**: 8px base unit. Scale: 4, 8, 12, 16, 24, 32, 48, 64, 80, 120
- **Border radius**: 3px (cards, badges), 6px (buttons, inputs), 8px (modals), 99px (pills, avatars)
- **Type scale**: 11px (xs), 13px (sm), 14px (base), 16px (md), 20px (lg), 30px (xl), 44px (2xl), 56px (3xl)
- **Weights**: 400 (regular), 500 (medium), 600 (semibold), 700 (bold)
- **Line heights**: 1.15 (display), 1.3 (headings), 1.6 (body), 1.75 (long-form)

### Motion

- **Standard timing**: `0.15s ease` for hover/expand/color. `0.3s` for slower transitions.
- **Entrance**: `fadeIn` — 6px translateY, 0.4s, 40ms stagger between siblings.
- **Running state**: `pulse` — 3s cycle, opacity dips to 0.55.
- Respect `prefers-reduced-motion` — always.

### Component Patterns

- **Cards**: surface bg, 1px border, no shadows. Hover = border-color change only.
- **Status dots**: green (running + pulse), orange (attention), red (error), dim (inactive)
- **Badges**: pill-shaped, dim background with saturated text
- **Buttons**: primary (accent fill), secondary (surface + border), ghost (text only). No hover lift or glow.
- **Inputs**: surface bg, border, 2px accent focus ring
- **Tabs**: underline style, grows from center on active
- **Tool indicators**: read (slate blue #7CA8C4) vs write (warm amber #C49B7C)
- **Section headings**: ABOVE the card, not inside. Uppercase, xs text, dim, tracking wide.
- **Settings row icons**: surfaceHover bg, textSecondary color (not bg/textDim — needs contrast)
